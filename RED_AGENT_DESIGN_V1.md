## Mandate & Fundamental Security Principle

> **CRITICAL SECURITY INVARIANT**  
> **"The LLM is an untrusted proposal generator. It is not an authorization authority and does not possess direct execution privileges."**  
>  
> **LLM OWNS REASONING. DETERMINISTIC INFRASTRUCTURE OWNS AUTHORITY.**

Every executable proposal generated by the LLM MUST strictly pass through the following deterministic authorization pipeline prior to hardware/container execution:

$$\text{RED LLM} \longrightarrow \text{Structured Proposal} \longrightarrow \text{Schema Validation} \longrightarrow \text{Novelty Evaluation} \longrightarrow \text{Safety Boundary} \longrightarrow \text{Policy Engine} \longrightarrow \text{ActionIR} \longrightarrow \text{HMAC SignedBlueprint} \longrightarrow \text{Simulation Adapter/Worker} \longrightarrow \text{Isolated Target}$$

## 1. Mission and Scope

### 1.1 Mission Statement
"Continuously explore an authorized cyber range to determine whether security detections can identify adversarial behaviors, discover detection blind spots, learn from experiment outcomes, and select increasingly informative experiments."

### 1.2 Scope & Boundaries
- **Authorized Range Only**: Operates strictly within designated, hardened target containers (`sentinelforge-target`).
- **No Production Access**: Strictly prohibited from interacting with external network assets, host infrastructure, or production tenants.
- **Strict Authorization Boundary**: Cannot issue raw shell commands, modify security policies, manage Docker sockets, generate HMAC keys, or directly alter database state.

## 2. Agent Architecture

The Red Agent operates as a closed reasoning-action loop governed by an external Python orchestrator.

```
                  ┌────────────────────────────────────────────────────────┐
                  │                 SECURITY OBJECTIVE                      │
                  └───────────────────────────┬────────────────────────────┘
                                              │
                                              ▼
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│                                   RED AGENT LOOP                                         │
│                                                                                          │
│   GOAL ──► OBSERVE ──► REASON ──► HYPOTHESIZE ──► PROPOSE ──► NOVELTY CHECK               │
│     ▲                                                               │                    │
│     │                                                               ▼                    │
│   LEARN ◄── DETECT ◄── OBSERVE ◄── EXECUTE ◄── SAFETY CHECK ◄───────┘                    │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

### Subsystem Components
1. **Context Engine (`context.py`)**: Assembles deterministic, tenant-isolated context from database records and memory stores.
2. **LLM Reasoner (`planner.py`)**: Interacts with the `ModelProvider` to form hypotheses and structured scenario proposals.
3. **Schema Validator (`schemas.py`)**: Enforces Pydantic typing on LLM output (`RedAgentDecision`).
4. **Novelty Engine (`novelty.py`)**: Computes `StrategyFingerprint` and classifies proposals (NOVEL, SIMILAR, DUPLICATE).
5. **Safety Boundary Bridge (`policies.py`)**: Evaluates proposals against `ExperimentSafetyBoundary` and `PolicyEngine`.
6. **Execution Orchestrator (`agent.py`)**: Translates approved proposals to `ActionIR`, requests HMAC signatures (`BlueprintSigner`), and dispatches to `SimulationWorker`.
7. **Observer & Memory (`memory.py` & `evaluator.py`)**: Captures execution outcomes, updates episodic/strategic memory, and feeds telemetry gap evaluations back to the agent.

## 3. Trust Boundaries

SentinelForge enforces three distinct security tiers:

| Tier | Component | Authorization Authority | Privileges |
| :--- | :--- | :--- | :--- |
| **Tier 1: Untrusted Reasoning** | Red LLM, Model Output, Raw Telemetry | **NONE** | Structured Proposal Generation Only |
| **Tier 2: Deterministic Control Plane** | PolicyEngine, Safety Boundary, BlueprintSigner, State Machine | **AUTHORITATIVE** | Policy Enforcement, HMAC Signing, Execution Gating |
| **Tier 3: Isolated Execution Sandbox** | `sentinelforge-target` Container, Linux Target | **NONE** | Unprivileged `labuser`, `cap_drop=ALL`, `read_only`, `tmpfs /tmp` |

### Hard Prohibitions
The Red Agent LLM MUST NEVER receive access to:
1. Docker daemon or Docker socket (`/var/run/docker.sock`).
2. Host filesystem or host networking.
3. Arbitrary shell execution outside `ExperimentSafetyBoundary`.
4. HMAC signing keys or key management interfaces.
5. PolicyEngine or Falco configuration files.
6. Database administration tools or cross-tenant data.

## 4. Red Agent State Machine

The Red Agent workflow is driven by a deterministic Python state machine (`state.py`). The LLM does NOT control state transitions.

```
       [IDLE] ──► [OBJECTIVE_RECEIVED] ──► [CONTEXT_LOADING] ──► [ANALYZING]
                                                                     │
                                                                     ▼
                                                         [HYPOTHESIS_GENERATED]
                                                                     │
                                                                     ▼
                                                          [SCENARIO_GENERATED]
                                                                     │
                                                                     ▼
                                                            [NOVELTY_CHECK]
                                                                     │
                                                                     ▼
                                                            [SAFETY_SUBMITTED]
                                                                │   │   │
                                         ┌──────────────────────┘   │   └─────────────────────┐
                                         ▼                          ▼                         ▼
                                      [DENIED]                 [ESCALATED]                [ALLOWED]
                                         │                          │                         │
                                         ▼                          ▼                         ▼
                                      [REFINE]                    [WAIT]                 [EXECUTING]
                                         │                                                    │
                                         └───────────────┐                                    ▼
                                                         │                               [OBSERVING]
                                                         │                                    │
                                                         ▼                                    ▼
                                                    [ANALYZING] ◄── [LEARNING] ◄─────── [EVALUATING]
                                                        │               │
                                                        ▼               ▼
                                                   [CONTINUE]      [FINISHED]
```

### State Definitions
- `IDLE`: Awaiting objective assignment.
- `OBJECTIVE_RECEIVED`: Security objective validated and initialized.
- `CONTEXT_LOADING`: Deterministic context assembly from database.
- `ANALYZING`: LLM generating hypothesis and strategy proposal.
- `HYPOTHESIS_GENERATED`: Hypothesis formed with expected observables.
- `SCENARIO_GENERATED`: Candidate `AdversarialScenario` proposed.
- `NOVELTY_CHECK`: Evaluated by deterministic `NoveltyEvaluator`.
- `SAFETY_SUBMITTED`: Proposal sent to `ExperimentSafetyBoundary`.
- `DENIED`: Proposal rejected by policy → transition to `REFINE` to adjust candidate actions.
- `ESCALATED`: Proposal requires human approval → transition to `WAIT`.
- `ALLOWED`: Approved by policy → converted to `ActionIR` and signed as `SignedBlueprint`.
- `EXECUTING`: Dispatched to `SimulationWorker` via `SimulationAdapter`.
- `OBSERVING`: Telemetry collected by Falco and `TelemetryNormalizer`.
- `EVALUATING`: Evaluated by `DetectionGapEvaluator` against `SigmaEngine`.
- `LEARNING`: Episodic and strategic memory updated with detection outcome.
- `CONTINUE`: Iteration check against budget -> returns to `ANALYZING`.
- `FINISHED`: Objective fully explored or budget limit reached.

## 5. RedAgentContext

Context is constructed deterministically by Python code before calling the LLM.

```python
@dataclass
class RedAgentContext:
    organization_id: UUID
    objective: SecurityObjective
    environment: Dict[str, Any]
    capabilities: List[str]
    experiment_history: List[Dict[str, Any]]
    detection_coverage: List[str]  # List of detected MITRE technique IDs
    detection_gaps: List[str]      # List of uncovered MITRE technique IDs
    previous_strategies: List[Dict[str, Any]]
    recent_observations: List[Dict[str, Any]]
    remaining_budget: Dict[str, int]
```

### Security Rule for Context Construction
- Context size is strictly bounded (max 5 recent experiment history entries, max 8KB text).
- Database queries MUST include `WHERE organization_id = :org_id` to guarantee tenant isolation.

## 11. StrategyFingerprint

Deterministic characterization of proposed strategies for novelty evaluation:

```python
class StrategyFingerprint(BaseModel):
    objective_id: UUID
    primary_technique: str
    normalized_executable: str
    normalized_command_pattern: str
    action_types: List[str]
    target_resource: str
    observable_classes: List[str]
    composite_hash: str

    @classmethod
    def create(cls, objective_id: UUID, actions: List[ActionProposalSpec]) -> "StrategyFingerprint":
        # Sort and normalize action representations
        norm_actions = []
        for a in actions:
            norm_cmd = f"{a.executable}:{' '.join(a.arguments)}"
            norm_actions.append(norm_cmd)
        
        raw_repr = f"{objective_id}|{'|'.join(norm_actions)}"
        comp_hash = hashlib.sha256(raw_repr.encode("utf-8")).hexdigest()
        
        primary_tech = actions[0].technique_id if actions else "T1059.004"
        primary_exe = actions[0].executable if actions else "/usr/bin/bash"
        
        return cls(
            objective_id=objective_id,
            primary_technique=primary_tech,
            normalized_executable=primary_exe,
            normalized_command_pattern=";".join(norm_actions),
            action_types=["process_exec"],
            target_resource=actions[0].target if actions else "sentinelforge-target",
            observable_classes=["process_creation"],
            composite_hash=comp_hash,
        )
```

## 12. NoveltyEvaluator

Evaluates proposal strategy fingerprints against episodic memory:

```python
class NoveltyStatus(str, Enum):
    NOVEL = "NOVEL"
    SIMILAR = "SIMILAR"
    DUPLICATE = "DUPLICATE"

class NoveltyEvaluation(BaseModel):
    status: NoveltyStatus
    similarity_score: float
    reason: str
    fingerprint: StrategyFingerprint
```

### Evaluation Logic
1. **DUPLICATE**: `composite_hash` exactly matches a previous experiment fingerprint.
2. **SIMILAR**: `primary_technique` and `normalized_executable` match a previous experiment, and command structure similarity $> 0.85$. Cosmetic argument changes (e.g., changing spaces or echo text) are classified as `SIMILAR` or `DUPLICATE`.
3. **NOVEL**: Materially different technique, executable, or action sequence.

## 16. Prompt-Injection Defenses

1. **Delimited Fencing**: Untrusted inputs (e.g., telemetry logs) are wrapped in `<UNTRUSTED_TELEMETRY>` blocks.
2. **Sanitization**: Null bytes, control characters, and nested XML tag attempts inside telemetry are stripped.
3. **Explicit Meta-Instructions**: System prompt instructs the model to ignore instructions contained within `<UNTRUSTED_TELEMETRY>`.
4. **Authoritative Boundary**: Prompt fencing is defense-in-depth only. The real security boundary is that LLM output is validated by Python schema rules and `ExperimentSafetyBoundary` before any execution occurs.

## 17. Safety Boundary Integration

Every proposed action inside a `RedAgentDecision` MUST be evaluated by `ExperimentSafetyBoundary` and `PolicyEngine`:

```python
# 1. Evaluate scenario risk level & human approval
scenario_decision = safety_boundary.evaluate_scenario(scenario, is_human_approved=False)
if scenario_decision.status != PolicyDecisionStatus.ALLOWED:
    return handle_rejection(scenario_decision)

# 2. Evaluate each action against exact policy allowlists
for action_spec in scenario.proposed_actions:
    action_ir = ActionIR(...)
    action_decision = safety_boundary.evaluate_action_ir(action_ir, org_id=org_id)
    if action_decision.status != PolicyDecisionStatus.ALLOWED:
        return handle_rejection(action_decision)

# 3. Only sign blueprints if ALL actions passed
signed_blueprints = [signer.sign(...) for action_ir in candidate_actions]
```

## 19. Failure Handling

- **Malformed Model Output**: Caught by Pydantic `ValidationError`. Retried with schema error message up to max format retries.
- **Provider API Timeout/Error**: Retried using exponential backoff. If max retries fail, agent gracefully pauses.
- **Safety Boundary Denial**: Transition to `DENIED` state. Policy reason is passed back to LLM context to prompt strategy refinement.
- **Simulation/Target Failure**: Logged as `SIMULATION_FAILURE`. Agent memory marks strategy as unverified and continues loop.

---

## 20. Retry Behavior

- **Max Schema/Format Retries**: 3 attempts per turn.
- **Max Safety Rejection Retries**: 3 attempts per objective.
- **Provider API Backoff**: 1s, 2s, 4s exponential backoff.

## 22. Termination Conditions

1. **OBJECTIVE_EXPLORED**: Objective space fully explored; no new allowed novel experiments remain.
2. **BUDGET_EXHAUSTED**: Iteration, experiment, LLM call, or wall-time limit reached.
3. **MAX_SAFETY_REJECTIONS**: Exceeded 3 consecutive safety boundary rejections.
4. **INFRASTRUCTURE_FAILURE**: Range target unreachable or failing health checks.

## 23. Evaluation Metrics

1. **Objective Exploration Rate**: Percentage of valid technique paths evaluated for an objective.
2. **Novelty Rate**: Ratio of `NOVEL` proposals vs `SIMILAR`/`DUPLICATE` proposals.
3. **Policy Authorization Rate**: Percentage of proposals passing `ExperimentSafetyBoundary`.
4. **Gap Discovery Rate**: Number of verified detection gaps identified per evaluation session.
5. **Adaptation Efficiency**: Iterations required to adapt strategy after a Blue remediation.

## 24. Security Test Matrix

| Category | Test Focus | Assertion |
| :--- | :--- | :--- |
| **Prompt Injection** | Simulated adversarial string in telemetry | Agent ignores instruction; boundary rejects unauthorized commands |
| **Schema Bypassing** | Malformed JSON or extra fields | Output parser rejects; schema error returned to agent |
| **Safety Violation** | Proposal with `rm -rf /` or `/etc/shadow` | `ExperimentSafetyBoundary` returns `DENIED`; no blueprint signed |
| **Novelty Bypass** | Cosmetic command tweak (`whoami` vs `whoami `) | `NoveltyEvaluator` flags as `SIMILAR`/`DUPLICATE`; execution skipped |
| **Tenant Contamination** | Request context for Org A | DB query strictly filters by Org A; Org B data inaccessible |
| **Budget Manipulation** | LLM output claiming `reset_budget()` | Ignored; external Python budget monitor enforces termination |
| **Infinite Loop** | Repetitive failed proposals | Max safety rejection threshold trips; agent terminates |
| **Replay Protection** | Re-submitting previous `SignedBlueprint` | DB unique constraint throws `IntegrityError`; execution blocked |

## 26. Threat Model

| Threat ID | Threat Name | Impact | Mitigation | Residual Risk |
| :--- | :--- | :--- | :--- | :--- |
| **T-01** | Telemetry Prompt Injection | Model hijacking | XML fencing, input sanitization, deterministic authorization boundary | Low |

| **T-05** | Blueprint Tampering | Unauthorized execution | HMAC-SHA256 signature verification | Zero |

| **T-08** | Budget Exhaustion / DoS | Resource exhaustion | Deterministic external Python budget tracker | Zero |
| **T-09** | Infinite Loop / Stagnation | Agent loop hang | Termination limits (`max_iterations`, `max_rejections`) | Zero |
| **T-10** | Cosmetic Novelty Spam | Wasteful execution | Deterministic `StrategyFingerprint` & `NoveltyEvaluator` | Low |

## 28. Explicit Non-Goals for V1

- Direct host shell or Docker socket access by the LLM.
- Unrestricted execution of arbitrary shell commands.
- Fine-tuning or local training of custom LLM models.
- Direct modification of Falco rules or Sigma rule sets by the Red Agent.
- Use of vector databases (PostgreSQL relational storage is authoritative for V1).
